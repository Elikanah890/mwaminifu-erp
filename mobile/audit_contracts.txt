# API Contract Audit

## GET /notifications
- **Flutter Request**: api.get('/notifications') - no shopId parameter
- **Expected Response**: Notification list for the user
- **Actual Response**: May return all notifications or fail without shop context
- **Discrepancy**: Calls /notifications without shopId - may return wrong data or fail silently
- **Fix**: Add shopId parameter to the call or ensure proper filtering
- **Priority**: Medium

## GET /shops/:shopId/dashboard
- **Flutter Request**: api.get('/shops/$shopId/dashboard') - uses shopId from ShopBloc
- **Expected Response**: Dashboard KPIs data
- **Actual Response**: Dashboard data loads correctly when shop is available
- **Discrepancy**: Race condition with postFrameCallback; fixed by using BlocListener + BlocBuilder
- **Fix**: Removed postFrameCallback; use direct data loading in build() method
- **Priority**: Critical

## GET /shops/:shopId/reports/:path
- **Flutter Request**: api.get('/shops/$shopId/reports/$path', queryParameters: {from, to}) - uses shopId and date filters
- **Expected Response**: Report data for all 9 types
- **Actual Response**: 2 of 9 types (employees, paymentMethods) have empty data sections in _buildDataSection
- **Discrepancy**: Report types employees and paymentMethods have empty _buildDataSection cases
- **Fix**: The data loading functions _employeesData and _paymentMethodsData already exist and work; the issue was the switch statement having bare 'break' statements for these types - fixed
- **Priority**: High

## POST /shops/:shopId/sales
- **Flutter Request**: api.post('/shops/$_shopId/sales', data: {'items', 'customerId', 'payments'})
- **Expected Response**: Sale creation response with receiptNumber, saleDate, grandTotal
- **Actual Response**: Sale creation works correctly; offline queue adds with shopId
- **Discrepancy**: Offline queue includes shopId; POS waits for shop to load before enabling
- **Fix**: POS _loadShop() waits for valid activeShopId before enabling POS functionality
- **Priority**: Critical
